# 跟单操作面板使用说明

面板运行在执行服务器上,需要 root 权限:

```sh
ssh -t <服务器别名> /opt/polycopy-engine/current/target/release/ops_panel
```

面板只读取数据库,不会下单、签名或撤单。私钥文件只检查是否存在,面板本身从不读取它的内容。

## 三个页面(按 1 / 2 / 3 切换,q 退出)

**1 总览**
- 三个服务(交易服务、盘口采样、飞书通知)的状态、运行版本和启动时间。
- 保险丝、待处理的异常单、配置检查结果、磁盘空间、最新一条 leader 信号的时间。面板里的时间都是服务器本地时间(北京时间);数据库里存的是 UTC,面板已自动换算。
- 窗口较窄时,服务表格会自动隐藏"说明"列,状态和启动时间始终完整显示。
- 账户额度:滚动 24 小时内已占用的额度和上限,算法和引擎下单前的检查完全一样。每笔挂出的单都按金额占用额度,不管最后成没成交,要过了 24 小时才释放。用到 80% 变黄、90% 变红,并显示最早的占用什么时候开始释放。
- 最近 24 小时的跟单情况:收到的信号、成交、挂单没成交、超时取消、被拒。
- ↑↓ 选择服务;s 启动,t 停止,r 重启。每个操作都要按 y 确认,并会先列出后果,例如"保险丝未清,启动后会立即退出"。

**2 日志**
- 实时查看所选服务的日志。←→ 切换服务。
- 每行只显示时间和内容,主机名、进程号等前缀已省略;今天的日志只显示时:分:秒,更早的会带上日期。放不下的长行会自动换行。
- i 只看重要内容(成交、拒单、熔断、报错),空格暂停,↑↓ / PgUp / PgDn 往前翻,End 回到最新。

**3 配置**
- 列出每个 leader 当前生效的全部参数,每项附中文说明。灰色表示该参数在当前模式下不起作用,例如设置了跟单比例后,"固定下单份数"就不生效。
- 账户与运行参数。
- 一致性检查:数据库、`persistent-public.env` 和运行参数这三处必须一致。显示红色时,交易服务启动会失败。
- e 修改配置(见下一节)。

## 修改配置

所有设置只在 `/etc/polycopy-engine/trading-config.json` 这一个文件里改。账户级参数写在 `runtime` 段,leader 的显示名写在 `display_name`。`persistent-public.env` 和数据库里的运行参数都由面板自动生成,不要手改。私钥仍单独放在 `credentials/copy-secrets.env`。

在配置页按 e:
1. 面板按数据库当前的实际配置重新生成一份待编辑的文件,并用 nano 打开。服务器上原来那份即使过时也不影响。
2. 改好后保存并退出 nano。
3. 面板在**数据库副本**上把改动完整试运行一遍。字段名拼错、数值超出范围、会导致启动失败的组合,都会在这一步被拦下,此时服务和数据**没有任何改动**。
4. 用中文逐项列出改动。停用 leader、改变允许运行的 leader 这类需要特别注意的改动,会用黄色或红色标出。
5. 按 y 应用,e 继续编辑,n 放弃。

按 y 之后依次执行:
1. 备份:修改前的配置和 env 存到 `/etc/polycopy-engine/archive/<时间>/`,数据库备份到 `/var/lib/polycopy-engine/backups/`。
2. 停止交易服务。如果只改了显示名,这一步和后面的写库、同步都会跳过,服务不中断。
3. 写入新的 trading-config.json,再用 `copy_config_apply` 写进数据库。
4. 重新生成 `persistent-public.env`,并执行 `persistent_control reconfigure` 同步运行参数。
5. 复查三处是否一致。
6. 问你是否启动交易服务:y 启动,n 暂不启动。

如果中途出错,交易服务会保持停止,这时可以按 r 回滚:恢复到修改前数据库里的真实配置,然后再决定是否启动。

## 飞书通知

通知程序是一个独立的小程序,只读数据库,并且以较低的 CPU 和磁盘优先级运行,不会拖慢交易服务的处理和下单。卡片分这几种:

| 卡片 | 含义 |
|---|---|
| Leader 出手(实时) | leader 刚成交,会触发跟单 |
| Leader 出手(REST 回填,不跟单) | 事后补抓到的成交,已过时效,不跟。一次超过 3 笔会合并成一张汇总 |
| FAK 吃单跟单成交 | 直接吃单成交,显示实付均价(常比限价低) |
| 开始挂单 | maker 挂单已上盘口,显示挂单价和到期时间 |
| 挂单成交 / 挂单部分成交 | 挂单被对手成交,按成交份数 × 挂单价计花费 |
| 挂单到期取消(未成交) | 到期没人成交,已自动撤销,没有买入 |
| 未跟上 | 被拒或失败,附中文原因 |
| 账户额度即将用满 / 已恢复 | 滚动 24 小时额度用到 90% 时提醒一次,回落到 80% 以下再报恢复;额度满期间因此被跳过的信号不逐条发,恢复时报总数 |
| 引擎已停止 / 已恢复运行 | 交易服务停了或重新起来 |

leader 名称显示 `trading-config.json` 里的 `display_name`,没有设置时显示数据库名称。

## 发布前提

配置页"单笔上限"的说明,描述的是"比例单超过上限时把份数压到上限以内"的行为(执行路径修复 89117c7)。面板必须和这个修复一起发布,或在它之后发布。
